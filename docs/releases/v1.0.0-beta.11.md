# Huf v1.0.0-beta.11

Beta 11 adds waiting, branching and per-member state to Flow, renames the Flow Run DocType, and fixes problems across chat, knowledge, memory, voice and forms.

## Breaking change: Flow Run is now Agent Flow Run

Frappe 16.61 ships its own `Flow Run` DocType, which collided with Huf's. Huf's DocType is now **Agent Flow Run**. This is a hard cut with no alias.

- Update any custom code, reports, API calls, SQL, `doc_events` hooks and client scripts that use `Flow Run` or `tabFlow Run` for Huf runs.
- A patch that runs during migrate renames the existing table and records, and repoints Link and Table fields on Huf DocTypes, including custom fields on them.
- Link or Table fields on other DocTypes are not changed. Repoint any of your own that meant Huf's runs.
- The patch renames `Flow Run` only when it belongs to the Huf module. If another app owns it at migrate time, the patch skips it and logs a message. In that case, check your earlier Huf run history after upgrading.
- Field names and labels are unchanged.

## Flow

### Wait, control and data steps
- **Wait step:** pause a run for a time, or until a reply or a resume link. Runs show as **Waiting Timer** and can be cancelled. A scheduled job wakes due runs, so the scheduler must be running.
- **New steps:** Choose by rules (switch), Stop, Find document, Update document and Run flow (sub-flow).
- **Retry and errors:** steps can retry with backoff, and a flow can have an error handler. A flow that ran its error handler always ends **Failed**, and errors from app-provided steps are shown in plain language.
- **Publish checks:** publishing now names unknown fields in Update document, flows that run themselves or an unpublished flow, steps from removed apps, and Wait or retry inside a loop.

### Member state
- **Flow Member State** keeps variables for each member of a flow across runs, readable in templates as `member.vars.<name>`.
- Entry policies control whether a member can enter a flow again.
- Inactive member state is purged daily (365 days by default). Flow state can also be kept forever, up to a configurable ceiling.

### Steps from other apps
- Apps can register their own Flow steps with the `huf_flow_nodes` hook. The builder shows them in the palette with a form built from their schema.

## Chat, agents and knowledge

### Behaviour changes to check
- **Skills:** an Optional skill is added to the system prompt only when Auto Load is on for both the skill and the agent's skill row. Other optional skills are listed and loaded on demand. This affects several seeded ERPNext skills.
- **Memory:** agents with memory enabled and no Memory Policy now save and recall memory automatically, per user and per agent.
- **Prompts:** saving a changed prompt body creates a new version.
- **Artifacts:** anyone who can open a conversation can read its artifacts. Export and save remain limited to the conversation owner and System Manager.
- **Automations:** Dedicated automations keep history per user when the agent persists user history.

### Added
- Stop queued and running responses, with recovery after gateway timeouts.
- The Hub can pass a business request to a matching agent and return its answer.
- Voice calls appear in chat history, and spoken language is detected automatically with an optional per-agent override.
- Knowledge accepts CSV uploads, deletes inputs in bulk and previews indexed text.

### Fixes
- Replies are kept when a second message arrives mid-run or another request writes to the conversation.
- Stopped runs and their messages stay visible after reload.
- Memory is not recalled into another user's session.
- Head bar actions are restored, and create, delete and import controls follow permissions.
- Further fixes to charts, artifacts, lists, forms, knowledge status, voice sessions and navigation.

## Tests and CI
- The temporary Frappe `v16.60.2` pin in server tests is removed.
- Frontend tests now run on Node 25 and later.
- File-size guard rules and UI verification guidance for contributors are updated.

## Upgrade

Back up the site first, then run:

```bash
bench --site <site> migrate
```

Then restart the bench and confirm the scheduler is enabled.
