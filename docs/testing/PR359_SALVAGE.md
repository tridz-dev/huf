## Bottom line

Nothing in PR #359 is dangerous to reuse, but almost none of it is a clean merge either. Given `mergeStateStatus: CONFLICTING` against a non-`develop` base, the pragmatic path is **not** to merge #359 as a unit, but to cherry-pick the confirmed **PORTABLE-GAP** items as small, independent PRs rebased onto current `develop`:

1. `flow_eval.py` + `agent_orchestration` test files (zero coverage today, security/scheduler-relevant)
2. Vitest jsdom + Testing-Library infra and component tests (zero `.tsx` test capability today)
3. `e2e-tests.yml` full-stack CI workflow + `seed_e2e_data.py` fixture seeder (the single biggest CI infra gap)
4. The `agent-tool-call`/`knowledge-rag`/`provider-settings` E2E *scenarios*, rewritten against current spec conventions

Everything else is either already covered (don't re-merge), needs a rewrite against a changed architecture (knowledge tests), or requires a separate status check before being treated as resolved (`#361` for the doctype-test bug spinoffs; SEC-004's deferred round-2 findings).
